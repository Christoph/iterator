* [Server applies plan on approve](plan-apply-on-approve.md) - ⬜ pending · 🟢 tests green · medium · When a plan submission carries apply:true and the browser returns plan-approved, the server spawns the writer itself with the approved sections, so plan text no longer round-trips through the model twice.

* [Single status module + server-computed derived state](status-module.md) - ⬜ pending · 🟢 tests green · medium · Create lib/status.mjs holding the feature-status transition table, readiness rule, and derived planStage; replace the scattered guards in write.mjs and gather.mjs; hub payload ships ready/waitingOn/stage and hub.mjs drops its client-side depSatisfied duplicate.
* [Planning tab: backlog, plan and feature management](planning-tab.md) - ⬜ pending · 🟢 tests green · large · depends: status-module, graph-full-labels · New planning view holding the no-plan hero, backlog (ideas/bugs), retired plans, dependency graph, stage-driven plan-lifecycle buttons, and read-only feature cards; hub slims to the Work surface; session shell gains the Planning tab.
* [Docs sweep: stale notes and tab description](stale-docs-cleanup.md) - ⬜ pending · small · depends: planning-tab · Remove the stale NUL-byte note from CLAUDE.md (the byte no longer exists in lib/gather.mjs) and align CLAUDE.md wording with the new tab structure.
* [Explain empty reviews instead of dead-ending](review-state-hints.md) - ⬜ pending · 🟢 tests green · small · When a non-done feature has no working-tree diff and no recorded commits, the hub and review flows say why (work likely committed outside the flow / wrong root) and what to do, instead of a bare 'working tree is clean'.
